# v4.1.2 — unpublished mobile development version

Based on the published main commit `f69a20ab1c39dfc3cdd314247f4f4e98182546f0`.
This branch is for local testing. It has not been merged into main or published.
“Offline” means unpublished here; AR still downloads its existing MediaPipe runtime/model when needed.

## Mobile reading and layout

- Keep Instrument Sans. Use 18px body text, 20px introductory text, 16px supporting text, and 14px fine print through 1023px wide.
- Use 48px primary controls and 44px carousel indicator hit areas.
- Keep the mobile menu through tablet widths, fit long titles, and respect the camera view's available height and bottom safe area.
- Stack AR previews on narrow phones; use two columns from 480px and three from 768px.
- Keep portraits centered. On narrow phones, put Lilian's audio invitation below her photo so its larger text does not overlap the portrait or name.

## AR rendering

- Run the same multiclass person segmentation in a dedicated classic worker. Try GPU acceleration, then CPU in the worker. Fall back to the main thread when worker support/initialization is unavailable.
- Submit one camera frame at a time. Transfer bitmaps and confidence arrays rather than queuing stale work.
- Pair each mask with the exact RGB frame that produced it. Preserve portrait proportions during inference preprocessing.
- Process person detail at up to 720px wide, retain a 1080×1920 final capture canvas, and composite the artwork/leaves/cloud/logo independently at up to 30fps.
- Stabilize small confidence changes, follow large changes immediately, and gently feather edges. Retain all non-background classes, including hair, skin and clothing.
- Adapt inference cadence to processing time, skip duplicate/hidden frames, and pause processing during video review.
- Keep the three experiences, camera/microphone permission, camera switching, audio mix, JPEG capture, recording preview/download and 60-second recording cap.

## Verification

- TypeScript strict check, ESLint, six targeted tests, production build and route prerendering passed locally.
- Home, Artwork, Events, About and AR checked at 320px and 768px; no document-level horizontal overflow. Phone screenshots also inspected at 390px.

## Run locally

`npm ci`, then `npm run dev`. Camera access works on localhost; opening the HTML directly from disk is not supported. Run `npm test`, `npm run lint`, `npx tsc --noEmit -p tsconfig.app.json`, and `npm run build` for checks.

The Netlify ignore command skips ordinary Git-triggered builds of branch `v4.1.2`. Other branches continue building. No pull request or manual deploy was created for this version.

References: [MediaPipe image segmentation](https://ai.google.dev/edge/mediapipe/solutions/vision/image_segmenter/web_js), [Netlify ignore builds](https://docs.netlify.com/build/configure-builds/ignore-builds/).

## Share links and free JPEG QR codes

Each AR card has a `share` link with a line link icon and a `QR code` button. Direct entry uses `?filter=<slug>` and opens the matching camera permission dialog after hydration; it never automatically grants camera/microphone access. Closing removes the filter parameter.

The QR dialog provides a clean public URL, a copy button, and a high-resolution JPEG download with a four-module white quiet zone. Codes are generated in the browser with the MIT-licensed `qrcode-generator`; no QR API, tracking redirect, account or subscription is involved. JPEG scan round-trip tests cover all three codes.

Public destinations (active with this behavior once v4.1.2 is published):

- https://smara.online/ar-experience/?filter=moonlit-lotus-pond
- https://smara.online/ar-experience/?filter=misty-mountain
- https://smara.online/ar-experience/?filter=tropical-beach

The local/branch `share` anchor stays on the current origin for testing. Exported QR codes and the copy button use the public destinations above.
